# Lunar Listings: web app

React 18 + TypeScript + deck.gl (Vite). A static site: it loads the files in `public/data/` and makes **no other
network requests** (works offline). The data is generated by the pipeline and must not be hand-edited.

## Run

```
npm ci
npm run dev        # dev server, http://localhost:5173
npm run build      # tsc --noEmit + production build to dist/
npm run preview    # serve dist/ at http://localhost:4173
npm test           # Vitest unit tests (about 1.5 s)
npm run lint       # eslint
npx playwright install chromium   # once
npx playwright test               # end-to-end tests against the production build (about 2.5 min)
```

Playwright builds and serves the app itself, but **reuses a server already running on port 4173**. Stop any
`npm run preview` first or you will test a stale build.

## URL modes

| URL | Effect |
|---|---|
| `?view=fit` | Start on the whole map instead of a random zoomed-in area |
| `?demo=1` | Adds a panel of preloaded scenarios (far-side bargain, Shackleton rim with 3D Tour, overlays) |
| `?present=1` | Large-type projector layout (1920×1080) |

## Source map (`src/`)

| Folder | Role |
|---|---|
| `data/` | Loads and decodes `cols.bin` into typed-array columns; lazy detail, horizon and overlay tiles; the data types |
| `worker/` | Web Worker that filters, sorts and ranks plots off the main thread (`compute.ts` is the logic, `client.ts` the promise wrapper) |
| `state/store.ts` | Zustand store (tab, tier, selection, hover, filters, sort, time). Components subscribe to single fields |
| `map/` | deck.gl map: dots at wide zoom, price pills when zoomed in, overlays, basemap, plot outlines |
| `results/` | The results list (virtualized), cards, home-type matching ("Plots for you") |
| `header/` | Filters, price inputs, time slider |
| `listing/` | Plot detail: scores, facts, badges, price rationale |
| `tour/` | 3D Tour of a polar plot (panorama from the terrain horizon, Sun and Earth tracks) |
| `science/` | TypeScript mirrors of the pipeline formulas (visibility, scoring, rent). Parity-tested against the Python golden vectors |
| `rent/` | Rent estimate UI and logic. Switched off by `RENT_ENABLED` in `features.ts` |
| `modes/` | `?demo` and `?present` handling |
| `ui/` | About dialog, glossary tooltips |

## Rules that matter

- **The Buy price never changes with UI state** (invariant D-6; an end-to-end test guards it).
- **`src/science/*` must match** `pipeline/tests/golden/*.json`. Do not loosen tolerances to make parity pass; fix the
  mirror or the pipeline. Constants come from `config.json`, never hard-coded.
- **Data contract:** the app is built for contract v2 (`docs/agents/CONTRACT.md`). A mismatch logs a warning. Need a
  new field? Ask Pipeline Claude via the log, don't invent it.
- **Performance:** the entry bundle is about 200 kB. The map (deck.gl) and the listing are lazy-loaded; keep heavy
  imports out of `App.tsx`. Subscribe to specific store fields (`useStore((s) => s.x)` or `useShallow`), never `useStore()`:
  hover changes on every mouse move and would re-render everything.

## Feature flag

`src/features.ts` exports `RENT_ENABLED` (currently `false`). It hides the Buy/Rent toggle, the Rent demo scenario and the
move-in shift button. The rent end-to-end spec is skipped while it is off. Set it to `true` to restore Rent.
